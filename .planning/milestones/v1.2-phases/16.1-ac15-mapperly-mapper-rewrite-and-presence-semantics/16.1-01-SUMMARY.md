# Phase 16.1: AC15 Mapperly Mapper Rewrite and Presence Semantics Summary

**Nullable AC15 wire presence with Mapperly-configured Green, Blue, and Yellow protocol projections**

## Performance

- **Duration:** 95 min

## Accomplishments

- Regenerated Green, Blue, and Yellow AC15 wire DTOs with `protogen +nullablevaluetype=yes` so optional primitive presence is represented as nullable generated properties.
- Removed production mapper dependence on protobuf `ShouldSerialize*` helpers; remaining usage is test-side wire presence assertions or generated wire internals.
- Converted AC15 mapper projection code to real Mapperly partial methods, including UserDataResponse maps configured with `MapProperty`, explicit `Use` conversions, and target ignores.
- Added adapter-level Mapperly defaults so automatic user mapping discovery is disabled and missing target mappings stay visible.

## Decisions Made

- Mapperly docs require configuration instead of suppressing diagnostics: AC15 adapters now use `MapperDefaults(AutoUserMappings = false, RequiredMappingStrategy = Target)`.
- Userdata fields that must serialize even when Common DTO values are absent are mapped with explicit `MapProperty(..., Use = ...)` conversions, not post-map object initializer code.
- `TokkunTutorialFlg` remains direct nullable-to-nullable so absent is still absent and explicit zero remains distinguishable from null.
