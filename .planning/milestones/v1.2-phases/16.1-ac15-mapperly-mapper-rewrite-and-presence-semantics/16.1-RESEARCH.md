# Phase 16.1: Research

## Findings

- Repo-local `.tools/protogen.exe --help` exposes `+nullablevaluetype={yes|no}`, which is the required generator option for nullable primitive properties when possible.
- Existing non-AC15 mapper code already uses Mapperly as intended, with bodiless partial mapping methods generated at build time.
- Current AC15 Green/Blue/Yellow mapper folders use mostly hand-written projection despite `[Mapper]` annotations.
- Production AC15 mapper references to `ShouldSerialize*` are concentrated in item-shop and playresult mappers, where optional primitive presence is being inferred from serializer helper methods instead of nullable contracts.
- Green, Blue, and Yellow adapter projects suppress Mapperly diagnostics globally with `RMG020;RMG012`, which makes fake or partial Mapperly adoption easier to miss.

## Regeneration Strategy

Use repo-local protogen for each AC15 era:

```powershell
.\.tools\protogen.exe --csharp_out=<adapter-wire-dir> -Iproto\<era> +nullablevaluetype=yes <proto-file>
```

Generate into a temporary directory first when verifying output names or namespace shape, then copy/regenerate into the adapter `Wire/` directory once the output is confirmed.

## Mapper Strategy

- Keep public mapper entry points where controllers/tests already call them.
- Add private or internal static partial Mapperly methods for mechanical mapping.
- Use wrapper methods only for transforms that need protocol semantics, null collection normalization, classification, or response composition.
- Let nullable generated optional primitive properties flow into nullable Common DTO properties directly.
- Remove production calls to `ShouldSerialize*` from Green, Blue, and Yellow mapper code.

## Verification Strategy

- `dotnet build TaikoLocalServer.slnx` or focused adapter builds must run Mapperly source generation and fail if partial methods are not generated.
- Reflection tests can assert nullable generated property shapes, for example optional tutorial and shop tutorial flags.
- Serialization tests can assert absent optional primitive fields stay absent while explicit zero remains present.
- Mapper behavior tests should assert Common DTO output values and response DTO fields, not mapper source text.
