# Phase 16.1: Validation

## Acceptance Gates

1. Green, Blue, and Yellow AC15 generated wire DTOs compile after regeneration with `+nullablevaluetype=yes`.
2. Production Green, Blue, and Yellow mapper code contains no `ShouldSerialize*` calls.
3. Green, Blue, and Yellow mapper projects use real Mapperly-generated partial methods for mechanical DTO projection.
4. Mapperly warning suppressions are removed or narrowed so fake Mapperly adoption is no longer hidden.
5. Tests prove nullable optional primitive presence and representative mapper behavior without source-text assertions.
6. A solution or focused adapter/test build passes.

## Risk Checks

- Nullable wire regeneration may expose compile errors where old code assumed non-null primitive values.
- Some generated optional repeated/message fields may keep non-null object helpers; this phase only requires nullable primitive presence where protogen supports it.
- Mapperly may need explicit ignore/map attributes for fields whose names differ between wire and Common DTOs.
- Yellow current worktree has unrelated pending files; stage only Phase 16.1 and mapper/protogen changes.
