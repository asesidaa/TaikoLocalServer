# Phase 23.1 Patterns: Don Challenge Refactor

**Date:** 2026-06-18

## Local Patterns To Follow

### Era Partial Handlers

`UpdatePlayResultCommandHandler` uses an unsuffixed dispatcher plus era partial files. Keep Red-specific save-data access, table selection, and reward mutators in `UpdatePlayResultCommand.Red.cs` or Red binding helpers. Shared logic may live in `Application/Ac15/*` only when the behavior is value-identical.

### Shared Writers With Explicit Bindings

Existing shared AC15 writers use small binding records:

- `Ac15NormalPlayTables<TPlay, TBest, TFavorite, TRecent>`
- `Ac15DaniTables<TScore, TStage>`
- `Ac15TokkunTables<TRecent>`

The Don Challenge writer should follow that style: direct `DbSet` inputs, small factory/apply delegates, and explicit save-data reward mutators. It should not add a repository or generic gameplay table.

### Unit Of Work

Normal-play Red mutation currently runs profile, Dani, Don Challenge, and normal-play writes in one request flow. `Ac15NormalPlayWriter.SaveAsync` saves the context. The Don Challenge writer should not force an extra save unless implementation discovers a correctness reason.

### Catalog Loading

Era catalogs resolve data through `PathHelper.GetDataPath(GameEra.Red)` and era catalog classes. Loader classes live in `Infrastructure/GameDataCatalog/Ac15`. A Don Challenge loader rename should preserve existing data-root behavior and should not hardcode `wwwroot/data/<era>`.

### Settings Compatibility

`EraSettings` currently binds old property names. Add DonChallenge-facing properties/accessors and preserve `EnableChallengeCompe` / `ActiveChallengeCompeBundleId` as aliases. Startup validation and catalog loading should call helper accessors so the new runtime code speaks Don Challenge.

### AdminApi Projection

`GetDonChallengeQueryHandler` should select era/capability data and call projection. Derived display values such as rule labels, target values, reward earned/locked state, and configured reward flags belong in a focused Don Challenge projection helper. This avoids Mapperly generated-source risk for nontrivial derived fields.

### Mapperly

If execution chooses Mapperly for any projection, it must:

- Keep mapper bodies source-generator driven.
- Run `dotnet build /p:EmitCompilerGeneratedFiles=true`.
- Inspect emitted `.g.cs` under `obj/.../generated/.../Riok.Mapperly/`.

Focused helpers are acceptable when they are simpler and more explicit.

### Tests

Per repo policy, tests should protect observable behavior:

- Red normal play writes Don Challenge progress/rewards and normal state.
- Red Tokkun does not write Don Challenge, normal, Dani, favorite, score, or unlock state.
- AdminApi readback stays read-only and does not opt users in.
- Config aliases work during transition.
- Migration review/build proves schema rename intent; avoid source-text tests over migrations.

Do not add tests over controller attributes, generated wire members, enum numbers, private methods, or route inventory.
