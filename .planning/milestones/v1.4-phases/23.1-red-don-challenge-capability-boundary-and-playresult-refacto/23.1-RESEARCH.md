# Phase 23.1 Research: Red Don Challenge Capability Boundary

**Date:** 2026-06-18
**Mode:** inline research, no subagents

## Summary

Red Don Challenge already works as a user-facing AdminApi feature and as normal-play playresult mutation, but most of the internal names still say `ChallengeCompe`. That conflates two distinct things:

- The real protocol route/wire surface: `challengecompe.php`, `CommonChallengeCompeResponse`, and generated `ChallengeCompe*` DTOs.
- The stateful game capability: monthly Don Challenge catalog, task progress, reward grants, locked-song readback, AdminApi projection, and Red persistence.

The refactor should rename the second category to Don Challenge while leaving the protocol category alone.

## Current Source Findings

| Area | Current Shape | Refactor Direction |
|------|---------------|--------------------|
| Shared capability code | `Application/Ac15/ChallengeCompe/*` owns catalog records, track definitions, progress evaluation, and reward decisions. | Rename to `Application/Ac15/DonChallenge/*` and `Ac15DonChallenge*` types. |
| Protocol route | `GetChallengeCompeQuery.*` handlers return empty compatibility responses for Green/Red/Yellow. | Preserve `ChallengeCompe` naming and no-state behavior unless new evidence proves otherwise. |
| Red playresult | `UpdatePlayResultCommand.Red.cs` contains inline `SaveRedChallengeCompeAsync`, reward grant logic, distinct-song progress, and raw fact writes. | Move this into shared `Ac15DonChallengeWriter` with Red binding records and direct `ITaikoDbContext`/DbSet use. |
| Red persistence | `RedChallengeCompeProgress` and `RedChallengeCompeRawFact` are concrete Red tables. | Rename to `RedDonChallengeProgress` and `RedDonChallengeRawFact` with data-preserving EF table/index/key renames. |
| Red catalog | `IRedCatalog.ChallengeCompe`, `RedEraGameDataCatalog.challengeCompe`, and `Ac15ChallengeCompeLoader` load `red_challenge_compe_data.json`. | Rename API/loader names to Don Challenge. Preserve current JSON filename as compatibility data unless a later data migration is justified. |
| Config | `EnableChallengeCompe` and `ActiveChallengeCompeBundleId` gate the Red catalog. | Add DonChallenge-facing settings and compatibility helpers that fall back to the old property names. |
| AdminApi | Routes and contracts already say Don Challenge, but `GetDonChallengeQueryHandler` hand-builds every task/reward DTO. | Move mechanical projection to focused helpers or Mapperly mappings. |
| Tokkun dispatch | Blue/Yellow/Red each duplicate `Is*TokkunShaped => PlayMode.Tokkun`. | Centralize the classifier/early-dispatch policy without creating a broad playresult pipeline. |

## Evidence And Constraints

- Red normal play currently filters valid normal stages before Don Challenge mutation. Don Challenge should continue using only those valid normal stages.
- Red Tokkun playresults return before normal, Dani, Don Challenge, favorites, best scores, and normal unlock writes.
- The existing `Ac15TokkunWriter` is already the right storage boundary for tutorial/recent-song writes. The missing abstraction is classification and early dispatch, not a new Tokkun persistence model.
- Existing `Ac15NormalPlayWriter` saves the DbContext after normal rows are added. The Don Challenge writer can participate in that same unit of work for normal play and does not need a separate save unless execution changes the ordering.
- Mapperly can be used for projection only if generated source is inspected after build. A focused projection helper is lower risk here because the projection has derived fields, reward flag checks, and rule labels.
- Existing tests are mostly Red observable behavior tests. Rename/update them where the underlying concept changes, but keep protocol mapper/stub tests using `ChallengeCompe` names where the real wire surface still uses that term.

## Risks

| Risk | Mitigation |
|------|------------|
| EF rename drops Red challenge data. | Use `RenameTable`, `RenameIndex`, and generated snapshot review; do not drop/create Red challenge tables in the rename migration. |
| Runtime code keeps old `ChallengeCompe` API names and leaks the boundary to White. | Update Application/Infrastructure capability APIs to `DonChallenge`; reserve old names for protocol route/wire DTOs and compatibility config aliases. |
| Shared writer hides era ownership behind a repository. | Use explicit era binding records with concrete DbSets, factories, and save-data reward mutators. |
| AdminApi projection rewrite changes readback semantics. | Keep response contracts stable and protect with existing Red AdminApi tests. |
| Tokkun cleanup accidentally broadens no-cross-mode behavior. | Use shared classifier only for `PlayMode.Tokkun`; era-specific handlers keep save-data/recent/history table ownership. |

## Recommended Plan Shape

1. Rename the Don Challenge capability, config accessors, Red storage entities/DbSets, and migration.
2. Add `Ac15DonChallengeWriter` and bind Red playresult mutation through it.
3. Move AdminApi projection to focused helper code and centralize Tokkun classifier/early-dispatch checks.
