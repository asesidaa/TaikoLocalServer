# Quick Task 260621-w8x: WebUI Era Selection and Capability Visibility

## Goal

Improve the WebUI era navigation so no-auth user cards do not flatten every era/page combination into one long menu, and make era feature visibility capability-driven so unsupported features are hidden while supported features stay visible.

## Source Facts

- `TaikoWebUI/Components/UserCard.razor` currently renders flat per-era menu items for profile and play-data links.
- `TaikoWebUI/Components/NavMenu.razor` already uses a selected era for logged-in navigation and only special-cases Don Challenge availability.
- `TaikoWebUI/Utilities/WebUiEra.cs` owns known WebUI era names and route helpers, but has no central WebUI feature matrix beyond Don Challenge.
- `Application/Ac15/Ac15EraProfiles.cs` currently gives every implemented AC15 era `Ac15ProfileCapabilities.CurrentFull`.
- `TaikoWebUI/Pages/ProfileEditor/Ac15ProfileEditor.razor` keeps Profile and Costume tabs separate through `ShowProfileOptions` and `ShowCustomization`; preserve that structure.
- `TaikoWebUI/Shared/Customize/TitlePicker.razor` labels the id picker as title plate even when AC15 passes `TitleSelectionMode.TitleId`.
- White and Murasaki must allow title customization without exposing title plate customization.
- Do not touch `proto/` or generated adapter `Wire/` files.
