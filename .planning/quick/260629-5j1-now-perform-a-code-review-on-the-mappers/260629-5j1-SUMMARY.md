# Summary

Reviewed AC15 generated wire nullability and playresult mapper helper usage. The root issue is inconsistent use of `.tools/protogen.exe +nullablevaluetype=yes`, not Mapperly itself.

`+nullablevaluetype=yes` makes optional proto value fields expose nullable public properties while preserving `ShouldSerialize*` presence methods. Required proto fields remain non-nullable and should not be changed without schema evidence.

The follow-up fix should add a tracked protogen regeneration entrypoint, regenerate affected White/Murasaki/Kimidori wire outputs, then simplify playresult mappers and missed legacy/final helper surfaces against the regenerated nullable types.

## Verification

- Inspected current wire and mapper sources for Blue, Green, Yellow, Red, White, Murasaki, Kimidori, and Momoiro.
- Ran `.tools/protogen.exe --help` and confirmed `+nullablevaluetype={yes|no}`.
- Probed `.tools/protogen.exe` with and without `+nullablevaluetype=yes` on White, Murasaki, Kimidori, Momoiro, Green, and Yellow proto inputs.
- Confirmed required playresult stage fields remain non-nullable after nullable-value regeneration.
