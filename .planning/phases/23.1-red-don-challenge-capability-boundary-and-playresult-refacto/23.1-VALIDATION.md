# Phase 23.1 Validation Plan

**Date:** 2026-06-18

## Observable Acceptance

1. Existing Red Don Challenge AdminApi responses remain available under current AdminApi routes and remain read-only.
2. Red normal playresult uploads still persist normal play, Dani when applicable, Don Challenge raw facts/progress, and Don Challenge reward flags in the same request flow.
3. Red Tokkun playresult uploads still update only Red Tokkun tutorial/recent-song state and do not write Don Challenge, normal score, crown, Dani, profile, favorite, normal unlock, battle, or shop state.
4. Existing Red ChallengeCompe protocol route/wire stub behavior remains compatibility-only and is not confused with Don Challenge state.
5. Red challenge data in existing databases is preserved by table/index/key renames.
6. Blue and Yellow Tokkun dispatch behavior remains unchanged except for using the shared classifier.

## Automated Checks

Run after implementation:

- `dotnet build TaikoLocalServer.slnx`
- `dotnet test Tests/Tests.csproj --filter "FullyQualifiedName~Red"`
- `dotnet test Tests/Tests.csproj --filter "FullyQualifiedName~BluePlayResultHandlerTests|FullyQualifiedName~YellowPlayResultHandlerTests"`
- `dotnet build Host/Host.csproj -o "$env:TEMP\TaikoLocalServer-host-build"`

Run after mapper changes only:

- `dotnet build TaikoLocalServer.slnx /p:EmitCompilerGeneratedFiles=true`
- Inspect relevant emitted Mapperly `.g.cs` files under `obj/.../generated/.../Riok.Mapperly/`.

Run after EF migration generation:

- Review the generated migration for `RenameTable`/`RenameIndex` style data-preserving operations.
- Confirm no generated operation drops `RedChallengeCompeProgress` or `RedChallengeCompeRawFacts` before rename.

## Test Boundaries

Add or adjust tests only where they protect behavior:

- Red Don Challenge persistence/readback/reward behavior.
- No-cross-mode behavior for Red Tokkun.
- Shared Tokkun classifier dispatch across Red/Blue/Yellow.
- Settings alias compatibility.

Do not add tests that assert source strings, migration source text, controller attributes, DI registration shape, generated wire property names, or one-to-one mapper copying.
