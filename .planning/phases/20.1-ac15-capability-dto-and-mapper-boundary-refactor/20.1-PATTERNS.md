# Phase 20.1: AC15 Capability DTO and Mapper Boundary Refactor - Pattern Map

**Mapped:** 2026-06-14
**Files analyzed:** 44 source/test/planning targets
**Analogs found:** 44 / 44

This pattern map intentionally replaces the old capability-list / mapper-dispatch pattern. The accepted target is:

1. Application handlers return behavior-named semantic sections or profiles.
2. Controllers instantiate final generated wire responses.
3. Controllers call generated Mapperly existing-target `Apply(section, [MappingTarget] response)` methods directly.
4. Mapper files contain Mapperly declarations plus mechanical conversion helpers only.
5. Tests protect observable behavior, wire presence, persistence boundaries, and generated-source inspection.

See `20.1-DESIGN-CONTRACT.md` for the compact boundary note. Its controlling rule is that controllers control final assembly; handlers and mappers do not.

Mapperly docs checked for this map:
- Existing-target mapping: https://mapperly.riok.app/docs/configuration/existing-target/
- Derived type mapping: https://mapperly.riok.app/docs/configuration/derived-type-mapping/
- Null value behavior: https://mapperly.riok.app/docs/configuration/mapper/#null-values
- Generated source inspection: https://mapperly.riok.app/docs/configuration/generated-source/

```csharp
private static byte[] ClearBits(byte[] source, IEnumerable<uint> ids, int byteCount)
{
    var result = Ac15ProtocolBytes.FixedOrZero(source, byteCount);
    var maxBits = byteCount * 8;
    foreach (var id in ids)
    {
        if (id >= maxBits)
        {
            continue;
        }

        result[id >> 3] &= (byte)~(1 << ((int)id & 7));
    }

    return result;
}

private static uint GetSafeDisplayDan(uint value, Ac15EraProfile profile)

        ? value
        : profile.Limits.SafeDisplayDanFallback;
```

The first replacement plan set was rejected by the plan-checker because BAID and userdata were too large and had non-runnable intermediate verification. The second set fixed architecture but still hit file-count gates. Use smaller compile-safe slices under the warning threshold where practical. Temporary compatibility fields are allowed only as an intermediate migration bridge and must be removed by the final slice for that endpoint family.

- Add BAID semantic section/profile properties without breaking unmigrated BAID eras.
- Migrate Blue and Green BAID handlers to populate semantic sections.
- Update Blue/Green BAID handler tests away from capability-list helpers where needed.
- Retain BAID capability compatibility only for Yellow/Red and mark it for Plan 04 removal.
