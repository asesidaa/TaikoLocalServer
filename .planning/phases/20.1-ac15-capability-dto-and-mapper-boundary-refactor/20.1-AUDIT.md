# Phase 20.1 DTO and Mapper Audit

Completed: 2026-06-14

## Scope

This audit covers nearby AC15 response DTO and mapper families after the BAID and userdata capability boundary refactor. Classifications use these meanings:

- `clean`: DTO shape already reflects a single response contract or value-identical shared behavior.
- `rename-only`: Mapperly attributes/helpers only rename fields, adapt nullable/presence shape, or place list fields into generated wire names.
- `refactor-later`: A future phase owns the behavior contract or evidence gap; no broad rewrite in Phase 20.1.
- `refactor-now`: Same kind of broad capability/union problem as BAID/userdata and small enough to fix in this phase.

## Mapperly Boundary Notes

- Acceptable mapper helpers in this audit are field renames, fixed-width/default array placement, null-to-wire-presence adaptation, and list item projection.
- Mapper helpers must not decide persistence, catalog lookup, mode classification, no-write boundaries, or unsupported capability support.
- The new BAID and userdata mappers use `MapPropertyFromSource` helpers to extract capability groups and preserve wire presence/defaulting. That is acceptable because the support decisions are made in application handlers and capability records, not in adapters.

## Cleanup Result

- Removed dead `CommonBaidResponse.Green.cs` and `CommonBaidResponse.Red.cs`.
- Removed dead `CommonUserDataResponse.Blue.cs`, `CommonUserDataResponse.Green.cs`, `CommonUserDataResponse.Yellow.cs`, and `CommonUserDataResponse.Red.cs`.
- Removed obsolete AC15-only fields from `CommonUserDataResponse.cs`.
- No generated `Wire/` files or proto inputs were modified.

## Deferred Items

- ChallengeCompe remains `refactor-later` for Phase 21. The current DTO/mapper can stay until the older-AC15 ChallengeCompe contract is evidence-backed.
- Initialdata can stay `rename-only`. A future rewrite should only happen if Blue battle advertisement fields or another concrete runtime requirement creates the same broad capability-union problem that BAID/userdata had.
