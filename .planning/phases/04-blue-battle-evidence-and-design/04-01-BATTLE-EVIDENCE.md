# Phase 04 Plan 04-01: Blue Battle Route And Wire Evidence

## Scope And Guardrails

This evidence pack covers BTEV-01 route/equivalent-client evidence and BTEV-02 proto-to-generated-wire ownership for the first Phase 4 battle slice. It is a planning artifact only. It does not approve battle runtime behavior, persistence, loaders, migrations, generated battle JSON, or replacement of the current `BattleUserDataController` stub.

Phase 4 follows the locked decisions from `04-CONTEXT.md`: D-01 accepts static client/proto evidence instead of requiring RPCS3 or cabinet logs in this phase; D-02 makes IDA/client behavior authoritative for wire/runtime mechanics when it disagrees with proto, generated wire, or XML; D-03 keeps wiki evidence to gameplay semantics only; D-04 requires traceable field-by-field evidence with citations; D-05 requires unresolved battle fields/defaults to be routed to case-by-case user approval before Phase 5 relies on them.

## Current Server State

- `initialdatacheck.php` is Mediator-backed and currently maps Blue common initial data through `InitialDataMappers.Map`. Battle fields exist in the common Blue DTO as nullable values and are only assigned when present, preserving protobuf omission semantics. Sources: `Adapters.GameProtocol.Blue/Controllers/InitialDataCheckController.cs:12`, `Application/Dtos/CommonInitialDataCheckResponse.Blue.cs:5`, `Adapters.GameProtocol.Blue/Mappers/InitialDataMappers.cs:29`.
- Current Blue initial data tests assert battle fields are omitted by default with `ShouldSerializeIsBattleplay`, `ShouldSerializeReleaseBattleStageFlg`, `ShouldSerializeReleaseBattleSpecialFlg`, and `ShouldSerializeBattleBondsLvCap` all false. Source: `Tests/Blue/BlueInitialDataTests.cs:30`.
- `battleuserdata.php` is Blue-owned but remains a Phase 4 read-only success stub returning `new BattleUserDataResponse { Result = 1 }`; it does not call Mediator. Sources: `Adapters.GameProtocol.Blue/Controllers/BattleUserDataController.cs:12`, `Tests/Blue/BlueRouteSkeletonTests.cs:61`.
- `playresult.php` sends current normal-mapped data into `UpdatePlayResultCommand(..., GameEra.Blue, common)`. `PlayResultMappers.Map` maps standard direct protobuf fields and does not map `AryBattlestagedata` or `AryReleaseBattledata` into common DTOs. Sources: `Adapters.GameProtocol.Blue/Controllers/PlayResultController.cs:12`, `Adapters.GameProtocol.Blue/Mappers/PlayResultMappers.cs:8`, `Adapters.GameProtocol.Blue/Mappers/PlayResultMappers.cs:64`.
- Existing mapper tests construct battle sections and assert the normal mapping still only preserves normal fields, which is the current no-inference baseline for Phase 4. Source: `Tests/Blue/BluePlayResultMapperTests.cs:61`.
