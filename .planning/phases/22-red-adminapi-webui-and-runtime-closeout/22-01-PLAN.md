# Plan 22-01 - Red Normal AdminApi Parity

<objective>
Expose Red-owned normal runtime state and catalog slices through the existing AdminApi surfaces used by the generic WebUI pages, while preserving era-owned persistence and no-cross-era boundaries. Covers D-01, D-02, D-03, D-04, D-15, and D-16.
</objective>

## Must Haves

- Red is accepted only on implemented normal readback surfaces: profile/user settings, play data, play history, favorites, leaderboard, Dani, game data, and customization catalog.
- Red AdminApi branches read and write only Red-owned `ITaikoDbContext.Red` tables and `IRedCatalog`.
- Red item-shop, battle, WaiWai, Banacoin, medal/shop-season, payment, coupon, wallet, and unproven controls remain absent.
- New tests assert observable controller behavior and cross-era isolation, not route attributes or source text.

## Decision Coverage

- D-01: Red normal AdminApi parity covers implemented AC15 readout surfaces.
- D-02: Red profile, favorite, customization, and supported settings edits use the existing AC15 edit model.
- D-03: Red normal readouts use existing `/api/{era}/...` AdminApi routes and generic WebUI contracts.
- D-04: compatibility-route diagnostics stay out of AdminApi/WebUI pages.
- D-15: tests cover Red-owned read/write boundaries and meaningful Red era routes.
- D-16: tests avoid superficial component/source-shape coverage.
