# Plan 22-03 - Red WebUI Routing And Don Challenge Page

<objective>
Enable Red in the existing generic WebUI pages and add the read-only Don Challenge page specified by the approved UI contract. Covers D-01, D-03, D-05, D-06, D-08, D-10, D-11, D-14, D-15, and D-16.
</objective>

## Must Haves

- Red is supported and AC15-classified by `WebUiEra`.
- Existing generic pages keep using era-preserving `/api/Red/...` routes through `WebUiEra.Api`.
- Don Challenge is a read-only page under Play Data and does not add opt-in or edit controls.
- Navigation hides Don Challenge unless availability reports an active supported bundle; direct unsupported routes render a neutral unavailable state.

## Decision Coverage

- D-01: WebUI era routing completes Red parity for implemented readout pages.
- D-03: generic WebUI pages continue using `/api/{era}/...`.
- D-05: Don Challenge is added as a standalone Play Data page.
- D-06: the page is capability-gated rather than Red-branded.
- D-08: challenge cards/progress are the main page content.
- D-10: configured reward status is visible on the page.
- D-11: navigation hides Don Challenge when no active bundle is configured.
- D-14: no opt-in toggle or editable opt-in field is added.
- D-15: tests cover Red route behavior, service routes, and navigation/page behavior.
- D-16: WebUI tests protect route and availability behavior only.

- The service does not inspect raw facts or opt-in fields because those are absent from the contract.

</acceptance_criteria>

Implement the approved UI contract:

- existing owner/admin redirect behavior
- breadcrumbs

- no opt-in toggle, no edit form, no raw facts, no user/BNG/global bucket display

Update `NavMenu.razor` so Don Challenge appears under Play Data only when the selected era is supported and availability is true. Availability should refresh when selected era changes.

</action>

- There are no in-page opt-in, authoring, raw-fact, diagnostics, WaiWai, battle, item-shop, medal, payment, coupon, wallet, or transaction controls.

<threat_model>

- Risk: enabling Red in the UI could surface unsupported controls. Mitigation: `IsAc15` hides Nijiiro-only controls and Don Challenge is availability-gated.
- Risk: direct unsupported routes could fall back to Nijiiro. Mitigation: use `NormalizeOrDefault` only for route normalization and render explicit unavailable state for Don Challenge responses.
- Risk: page content could expose raw protocol/debug details. Mitigation: use only Don Challenge AdminApi contracts and copy from the UI spec.
- Risk: mobile layout can overlap long task names. Mitigation: use responsive grids, wrapping text, and stable task-card dimensions.
</threat_model>
