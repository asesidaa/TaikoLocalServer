# Plan 20-03 - Red Playresult, Dani, Tokkun, And Compatibility Runtime

## Goal

Persist Red normal play and Dani through existing shared writers, classify Red Tokkun as tutorial-only state, and keep simple compatibility routes non-authoritative.

## Tasks

1. [x] Add Red playresult mapper/controller and handler.
   - Map Red playresult wire to `CommonPlayResultData`, including Don points, reward progress, difficulty fields, Tokkun fields, and ChallengeCompe arrays.
   - Route Red playresult through `UpdatePlayResultCommand`.
   - Filter normal stages through shared AC15 normal-stage filtering.

2. [x] Persist Red normal play and Dani.
   - Update Red save-data counters, Don points, difficulty/tutorial fields, current costume, and unlock flags with Red-specific limits.
   - Use `Ac15NormalPlayWriter` for Red play/best/favorite/recent rows.
   - Use `Ac15DaniWriter` for Red Dan score/stage rows and save-data Dan flags/display-Dan.

3. [x] Add tutorial-only Red Tokkun handling.
   - Detect Tokkun before normal/Dani/Challenge behavior.
   - Update only Red `TokkunTutorialFlg` when present.
   - Do not add raw Tokkun history rows or normal/Dani/reward/unlock writes.

4. [x] Preserve simple compatibility routes.
   - Keep reward-card, reward-execution, balance-check, Banacoin payment, and Banacoin error routes log-and-success.
   - Add no-write coverage where compatibility requests include unlock or payment-looking fields.

## Verification

- Focused Red playresult, Dani, Tokkun, and compatibility tests.
- No-cross-era/no-cross-mode assertions over persisted rows.
