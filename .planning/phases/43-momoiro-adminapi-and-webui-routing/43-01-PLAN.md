# Phase 43 Plan 01: Momoiro AdminApi and WebUI Routing

## Objective

Wire implemented MOMOIRO-owned state into the existing AdminApi and WebUI routing surfaces while keeping unsupported MOMOIRO feature controls absent.

## Tasks

1. Add MOMOIRO WebUI era support.
   - Update `WebUiEra` constants, supported/known era lists, and AC15 detection.
   - Keep Don Challenge support limited to Red and White.

2. Add MOMOIRO AdminApi controller dispatch.
   - Add switch arms for MOMOIRO in game data, profile settings, play data, play history, favorites, leaderboards, Dan best data, and customization catalog controllers.
   - Implement MOMOIRO partial methods over MOMOIRO-owned EF sets only.
   - Preserve `MomoiroFavoriteSongs.DisplayOrder` for read/write.

3. Add MOMOIRO catalog customization endpoints.
   - Extend `IMomoiroCatalog` with read-only customization lookup methods.
   - Return empty runtime customization catalogs until MOMOIRO-specific evidence exists.
   - Do not borrow adjacent-era customization data.

4. Add focused tests.
   - Cover Momoiro AdminApi read/write behavior over Momoiro tables and adjacent-era isolation.
   - Cover WebUI era normalization, route helpers, DanData init route, catalog lookup routes, and Don Challenge absence.

5. Verify and close.
   - Run focused Momoiro/AdminApi/WebUI tests.
   - Run solution and temp-output Host builds.
   - Update Phase 43 validation, requirements, roadmap, and state without claiming Phase 44 cabinet/RPCS3 acceptance.
