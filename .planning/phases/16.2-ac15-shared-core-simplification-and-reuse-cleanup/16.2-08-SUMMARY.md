# Phase 16.2 Plan 08: AC15 Row-Shape EF Helper Architecture Summary

**Narrow AC15 row-shape interfaces and generic EF helpers now remove duplicated storage algorithms while preserving era-owned tables and direct DbSet binding.**

## Accomplishments

- Added six narrow Domain storage-shape interfaces for identical AC15 Dan score, Dan stage score, song best, favorite song, recent song, and shop season rows.
- Implemented those interfaces on Blue, Green, and Yellow entities without adding shared EF base classes, discriminator tables, or navigation-property contracts.
- Refactored `Ac15DaniService` so score readback, summary readback, score upsert, and stage upsert share generic row-shape helpers while each era still selects its concrete `DbSet` and Mapperly overload.
- Refactored `Ac15NormalPlayService` so best-score updates, favorite maintenance, recent upsert, and recent trimming use generic helpers over concrete era `DbSet`s.
- Refactored `Ac15ItemShopService` so purchased item lookup and purchase-row insertion use typed generic helpers while unlock behavior remains explicit per era.

## Decisions Made

- The accepted hybrid architecture is now represented in code: shared algorithms use narrow row-shape contracts, while binding stays explicit through `ITaikoDbContext`.
- Generic helpers avoid relying on interface-property EF translation when a query predicate can be supplied as a concrete entity expression at the era binding edge.
- The favorite helper now consistently counts both persisted and tracked unsaved favorites for all AC15 eras, matching the existing Blue/Yellow multi-stage cap behavior and preventing an in-flight Green payload from overfilling the cap before `SaveChanges`.
