# Phase 16.2 Code Review

Behavior verification passed, but this review found one concrete regression risk and three architecture issues that support the design concern: Phase 16.2 preserved era boundaries, but it did not simplify shared AC15 behavior enough.

## Critical Issues

### CR-01 - Green normal play discards compact cabinet timestamps

**File:** `Application/Handlers/UpdatePlayResultCommand.Green.cs:43`

Green still parses `playResultData.PlayDatetime` with plain `DateTime.TryParse`, while AC15 cabinet payloads use compact `yyyyMMddHHmmss`. Blue and Yellow call the shared exact-format parser, and `Ac15NormalPlayService` also uses the shared parser for play/recent rows. Green can therefore persist upload time in `UserSaveDataGreen.LastPlayDatetime` while the rows saved by the shared normal-play service use cabinet play time.

**Fix:** use `ParseAc15PlayDatetimeOrNow(playResultData.PlayDatetime)` in Green and add a regression asserting Green `LastPlayDatetime` for a compact timestamp.

## Warning Issues

### WR-01 - Table-only era switches remain scattered through shared services

**Files:** `Application/Ac15/Ac15NormalPlayService.cs`, `Application/Ac15/Ac15DaniService.cs`, `Application/Ac15/Ac15ItemShopService.cs`

The shared services still switch by era at most storage operations instead of binding concrete era DbSets once and running one generic algorithm. Examples: `Ac15NormalPlayService` switches in recent, save, play-row, best, and favorite helpers (`:87`, `:108`, `:128`, `:149`, `:200`, `:275`); `Ac15DaniService` switches for read/upsert flows (`:90`, `:116`, `:141`, `:167`); `Ac15ItemShopService` uses `Ac15ItemShopSaveRows` plus switches for season lookup, purchase lookup, insertion, and unlock dispatch (`:119`, `:151`, `:193`, `:241`, `:376`).

**Recommendation:** keep direct EF visible, but introduce narrow typed binding records at service entry. Bind DbSets and Mapperly delegates once, then call a generic implementation. This preserves separate era tables without the rejected repository-shaped adapter layer.

### WR-02 - Era playresult handlers still own most shared AC15 save mutation

**Files:** `Application/Handlers/UpdatePlayResultCommand.Blue.cs`, `Application/Handlers/UpdatePlayResultCommand.Green.cs`, `Application/Handlers/UpdatePlayResultCommand.Yellow.cs`, `Application/Handlers/UpdatePlayResultCommand.Ac15.cs`

Blue and Yellow carry the same broad save sequence (`Blue.cs:38-114`, `Yellow.cs:42-114`), with Green largely matching (`Green.cs:28-106`). The handlers still perform common save lookup, active shop season lookup, medal checks, Don/Katsu mutation, tutorial/profile fields, costume/unlock bits, counters, Dani save, and normal-play save. Yellow is especially noisy because its unique behavior is mostly Tokkun routing, stage filtering, and WaiWai logging.

The handlers also parse/filter before calling `Ac15NormalPlayService`, which then repeats user/save/stage validation and play-time parsing (`Ac15NormalPlayService.cs:20`, `:34`, `:38-46`, `:426`). Ownership of normal-play acceptance is split.

**Recommendation:** introduce a shared typed `Ac15PlayResultSaveService`. Era handlers should route special modes and era-only edges: Blue Tokkun/battle, Green ghost/AI, Yellow Tokkun/WaiWai diagnostics.

### WR-03 - Item-shop edge behavior is split between handlers and service

**Files:** `Application/Handlers/ItemPurchaseCommand.Green.cs`, `Application/Handlers/ItemPurchaseCommand.Yellow.cs`, `Application/Ac15/Ac15ItemShopService.cs`

Blue delegates directly to `Ac15ItemShopService`, but Green handles no-active-season and empty-season cases first (`ItemPurchaseCommand.Green.cs:14-27`), while Yellow handles unsupported requested items with a local season-state query (`ItemPurchaseCommand.Yellow.cs:16-54`). The shared service also owns active-season, preflight, validation, purchase, unlock, and response behavior (`Ac15ItemShopService.cs:59-116`).

**Recommendation:** move active-season-missing, empty-season preflight, and unsupported-item behavior into `Ac15ItemShopService` as explicit per-era policy inputs. Keep handlers responsible for choosing catalog/save data only.

## Notes

No evidence found that the rejected repository-shaped `IAc15*Persistence` layer returned. Era-owned EF tables remain separate. The problem is that shared behavior is still spread across era switches and handlers, so future shared changes still require multi-era edits.
