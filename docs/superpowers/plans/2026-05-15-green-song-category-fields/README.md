# Green Song Category & Recommendation Fields Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the dead category/pushed/favorite/recent counters on `UserSaveDataGreen` end-to-end, plumb the per-stage `IsPushed` bit, fix the recently-played folder ordering, enforce the Green-era 5-favorite cap, and add an operator-configured recommend-songs catalog.

**Architecture:** Counters are aggregated by a new pure `GreenProfileCounters` static helper invoked once per stage from `UpdatePlayResultCommand.Green.HandleGreen`. Pushed-song advertisement uses a new `IGreenCatalog.Recommend` member sourced from `wwwroot/data/green/recommend_songs.json` via a sibling loader matching the existing Green loader pattern. The recently-played folder gets a `LastPlayed` column with server-tracked upsert + trim-to-10 semantics; favorites get a count-check before insert.

**Tech Stack:** C# 13, .NET 10, Entity Framework Core 10 with SQLite migrations, xUnit, Mediator handlers, Riok.Mapperly source-generated mappers, protobuf-net.

## Execution Rules

- Execute tasks in order. Each task ends with a commit.
- Do not change the `IsFavorite` toggle semantics on the play-result path beyond adding the 5-favorite cap. Rewriting toggle semantics is explicitly out of scope.
- Do not change Nijiiro counters or DTOs. None of the new fields live on the Nijiiro partial.
- Do not edit existing migration files. New migration only.
- Do not introduce profile-aware (`gender_type`/`player_age`) recommendation logic. Recommendations are global.
- Counter saturation: at `uint.MaxValue` the counter freezes silently — do not throw or wrap.
- Favorites cap: at 5 entries an additional insert is silently dropped. Removes are always allowed.
