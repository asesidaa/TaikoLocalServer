# T9 — Rewrite AuthController

Phase 2.16.7. Self-contained.

**Pre-state**: T8 done. The 8 simple admin controllers + GameDataController have been rewritten. Only `AuthController` (~271 LOC) and `AuthService` are left consuming the wrapper pattern. The build for `TaikoLocalServer/Controllers/Api/AuthController.cs` and `TaikoLocalServer/Services/AuthService.cs` is what's still red — everything else compiles.

**Risk #3 from spec §8**: `AuthController.Login` issues a JWT. The expiration value (`Expires = DateTime.UtcNow.AddDays(1)` or similar) is the highest-risk diff in this entire PR. T5 lifted that into `JwtTokenService.IssueToken`. Verify Login now calls `jwtTokens.IssueToken(baid, isAdmin)` with no inline JwtSecurityTokenHandler logic surviving in AuthController. If the call signature drops a parameter, session lifetime silently changes.

## Step 1 — Read the old controller and service

```bash
cat TaikoLocalServer/Controllers/Api/AuthController.cs
cat TaikoLocalServer/Services/AuthService.cs
```

The current AuthController injects `IAuthService authService, IUserDatumService userDatumService, IOptions<AuthSettings> settings` (or similar). Its actions: `Login`, `Register`, `ChangePassword`, `Logout`, plus OTP setup/verify endpoints.

`AuthService` has methods like `GetCardByAccessCode`, `RegisterUser`, `ChangePassword`, `IsAdmin`, OTP secret encryption helpers, plus `ExtractTokenInfo` (already lifted to `JwtTokenService` in T5).

## Step 2 — Plan the rewrite

The new constructor:

```csharp
public class AuthController(
    ITaikoDbContext context,
    IJwtTokenService jwtTokens,
    IOptions<AuthSettings> settings) : BaseController<AuthController>
```

For each existing AuthController action:
- Replace `authService.GetCardByAccessCode(code)` → `await context.Cards.FirstOrDefaultAsync(c => c.AccessCode == code)`. (Read AuthService for the exact LINQ shape.)
- Replace `authService.IssueToken(baid, isAdmin)` (or the inline `JwtSecurityTokenHandler` block) → `jwtTokens.IssueToken(baid, isAdmin)`. **Verify the inline block is gone after the rewrite.**
- Replace `authService.RegisterUser(...)` → inline the body (creates `UserDatum`, `Card`, `Credential`, hashes password with `BCrypt.Net.BCrypt.HashPassword(...)`).
- For password verification: `BCrypt.Net.BCrypt.Verify(password, credential.PasswordHash)`.
- For `SaveChanges`: `await context.SaveChangesAsync(HttpContext.RequestAborted);`

### OTP secret-handling — copy verbatim

`AuthService` likely has methods like `EncryptOtpSecret(secret, baid)` / `DecryptOtpSecret(...)` using AES with a key derived from `AuthSettings.JwtKey` or similar. **Move these helper methods into a private static class on AuthController** (or duplicate into AuthController as private methods — copy line by line).

The AES encryption parameters (key derivation, IV generation, mode) are crypto-critical. **Do not refactor or "improve" them** — copy each line. Re-deploy compatibility depends on bit-identical encryption: existing encrypted secrets in the DB must still decrypt correctly.

If the OTP logic is more than ~80 lines, consider creating `Infrastructure/Identity/OtpSecretCipher.cs` as a static helper class — but that's optional refactoring. The fastest path is to inline the methods on AuthController and refactor in a follow-up.

## Step 4 — Capture baseline (Risk #3 verification)
